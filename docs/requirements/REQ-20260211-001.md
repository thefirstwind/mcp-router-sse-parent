# getUserById 泛化调用参数类型错误

## 需求来源

用户报告：建立SSE连接之后，调用 `com.pajk.provider3.service.UserService.getUserById` 报错

## 根本原因分析

从日志可以看到关键错误：

```
Caused by: java.lang.NoSuchMethodException: com.pajk.provider3.service.UserService.getUserById(int)
        at java.base/java.lang.Class.getMethod(Class.java:2227)
        at com.alibaba.dubbo.common.utils.ReflectUtils.findMethodByMethodSignature(ReflectUtils.java:809)
        at com.alibaba.dubbo.rpc.filter.GenericFilter.invoke(GenericFilter.java:59)
```

### 问题根源

**参数类型不匹配**：
- 泛化调用传递的参数类型：`int`（基本类型）
- 实际方法签名期望的类型：`Long`（包装类型）

在 Dubbo 泛化调用中，`int` 和 `Long` **不能自动转换**，必须显式指定正确的类型。

### 影响代码位置

`McpExecutorService.java` 中的类型推断逻辑：

```java
// 当前实现：基于数据库的 parameter_type 字段
String parameterType = param.getParameterType();  // "Long"
Object argValue = convertArgument(arg, parameterType);  // 可能错误地推断为 int
```

## 验收标准

## 实施计划

### 方案 1: 修正参数类型推断（推荐）

修改 `McpExecutorService.java` 的类型转换逻辑：

```java
private Object convertArgument(Object arg, String parameterType) {
    // 优先使用数据库的 parameter_type
    if (parameterType != null) {
        return convertByType(arg, parameterType);
    }
    
    // 回退：基于参数值推断
    if (arg instanceof Number) {
        // 特殊处理：数字类型需要精确匹配
        return convertNumber((Number) arg, parameterType);
    }
    
    return arg;
}

private Object convertNumber(Number value, String targetType) {
    if ("Long".equals(targetType) || "java.lang.Long".equals(targetType)) {
        return value.longValue();
    }
    if ("Integer".equals(targetType) || "java.lang.Integer".equals(targetType)) {
        return value.intValue();
    }
    // ... 其他类型
    return value;
}
```

### 方案 2: 检查数据库参数类型记录

确保 `zk_dubbo_method_parameter` 表中的 `parameter_type` 正确：

```sql
SELECT * FROM zk_dubbo_method_parameter 
WHERE dubbo_service_method_id IN (
    SELECT id FROM zk_dubbo_service_method 
    WHERE method_name = 'getUserById'
);
```

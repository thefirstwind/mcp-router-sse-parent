# 虚拟节点注册使用arg0/arg1而非真实参数名

## 需求来源

用户反馈：虚拟节点注册流程中，参数名显示为 `arg0`, `arg1` 等默认名称，而非真实的参数名（如 `userId`），导致用户必须查看源码才知道应该传什么参数。

## 根本原因分析

### 问题核心

1. **JAR扫描使用ASM读取class文件**
   - Java接口（interface）编译后的class文件**不包含参数名信息**
   - 接口方法是抽象的，没有方法体和LocalVariableTable
   - 即使有 `-parameters` 编译选项，接口也只在Parameter注解中包含参数名

2. **当前实现的问题**
   - `JarScannerService.java` 第176行：硬编码使用 `"arg" + i`
   - 没有尝试读取 Parameter 注解或其他元数据

### 代码位置

**文件**: `JarScannerService.java` (Line 148-196)

```java
// 当前实现
String paramName = "arg" + i; // 硬编码默认参数名
```

## 解决方案

### 方案1: 增强ASM扫描（✅ 已实施）

修改 `JarScannerService.java`，利用ASM的以下功能：
1. `visitParameter()` - 读取Parameter注解（需要 `-parameters` 编译）
2. `visitLocalVariable()` - 读取LocalVariableTable（接口不适用）

**限制**: 需要源JAR包使用 `-parameters` 编译选项。

**状态**: ✅ 已完成

---

### 方案2: 使用反射API

对于已加载到classpath的类，可以用Java反射获取参数名：

```java
Method method = Class.forName(className).getMethod(methodName, paramTypes);
Parameter[] parameters = method.getParameters();
for (Parameter param : parameters) {
    String name = param.getName(); // userId, orderId等
}
```

**优点**: 
- Java 8+ 内置功能
- 不依赖编译选项
- 更准确可靠

**缺点**:
- 需要类在classpath中
- 对于扫描JAR可能需要动态加载

**状态**: 可选补充

---

### 方案3: 要求provider编译时添加-parameters（✅ 已实施）

修改所有provider的pom.xml：

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <configuration>
        <parameters>true</parameters>
    </configuration>
</plugin>
```

**优点**: 根本解决，所有参数名都包含在class文件中  
**缺点**: 需要所有provider配合修改

**状态**: ✅ demo-provider3 已添加

---

### 方案4: 从GitLab/GitHub源代码分析（🌟 推荐方案）

**核心思路**: 虚拟节点创建时，从源码仓库（GitLab/GitHub）获取Java源文件，直接解析参数名。

#### 实现方案

**步骤1: 获取源代码**
```java
// 从GitLab/GitHub API获取源文件
// 假设项目配置了Git仓库信息
String gitRepoUrl = project.getGitRepo(); // 如: https://github.com/user/repo
String interfaceFile = "src/main/java/com/pajk/provider3/service/UserService.java";

// 使用GitLab/GitHub API下载源文件
String sourceCode = gitApi.getFile(gitRepoUrl, interfaceFile, "main");
```

**步骤2: 解析Java源代码**
```java
// 使用JavaParser解析源文件
CompilationUnit cu = StaticJavaParser.parse(sourceCode);

// 查找接口和方法
Optional<ClassOrInterfaceDeclaration> interfaceDecl = cu.findFirst(
    ClassOrInterfaceDeclaration.class,
    c -> c.getNameAsString().equals("UserService")
);

// 提取方法参数名
MethodDeclaration method = interfaceDecl.get().getMethodsByName("getUserById").get(0);
List<String> paramNames = method.getParameters().stream()
    .map(p -> p.getNameAsString())
    .collect(Collectors.toList());

// paramNames = ["userId"]
```

**优点**:
- ✅ **最可靠**: 源代码永远包含真实参数名
- ✅ **不依赖编译选项**: 无论如何编译都能获取
- ✅ **支持旧项目**: 即使没有-parameters也能工作
- ✅ **可作为降级方案**: class文件读取失败时的备选
- ✅ **额外信息**: 还能获取JavaDoc注释、参数说明等

**缺点**:
- ⚠️ 需要配置Git仓库地址
- ⚠️ 需要网络访问（可以缓存）
- ⚠️ 需要额外依赖（JavaParser或其他Java源码解析库）

**推荐库**:
- **JavaParser**: https://github.com/javaparser/javaparser
  ```xml
  <dependency>
      <groupId>com.github.javaparser</groupId>
      <artifactId>javaparser-core</artifactId>
      <version>3.25.7</version>
  </dependency>
  ```

**实施优先级**: 🌟🌟🌟🌟🌟 **强烈推荐**

---

### 综合方案（推荐）

**三级降级策略**:

```
1️⃣ 优先：从GitLab/GitHub源代码解析（最可靠）
   ↓ 失败
2️⃣ 降级：从class文件MethodParameters读取（需要-parameters）
   ↓ 失败  
3️⃣ 兜底：使用默认参数名 arg0, arg1...
```

**伪代码**:
```java
List<String> getParameterNames(String interfaceName, String methodName) {
    // 方案4: 尝试从源代码获取
    try {
        return getParameterNamesFromSourceCode(interfaceName, methodName);
    } catch (Exception e) {
        log.debug("无法从源代码获取参数名: {}", e.getMessage());
    }
    
    // 方案1: 尝试从class文件MethodParameters获取
    try {
        return getParameterNamesFromClassFile(interfaceName, methodName);
    } catch (Exception e) {
        log.debug("无法从class文件获取参数名: {}", e.getMessage());
    }
    
    // 兜底: 使用默认参数名
    return generateDefaultParameterNames(paramCount);
}
```
